## A7. Functionality
- Flow: Splash → Login (or Forgot password) → Home dashboard → bottom tabs / drawer modules / profile modules.
- Data flow: all state in `App.tsx`, passed as props + callbacks (`onSubmit`, `onBack`, `onToast`). Manager decisions update shared records → Staff sees result; `pushNotification('Staff'|'Manager', …)` feeds role inboxes.
- Forms: inline validation, disabled CTA until valid, success modal/toast.
- Filters/search: filter sheets + text search in lists/drawer.
- Notifications: per-role list, unread badge, deep-link to module.
- No real API, no persistence (reset button restores seeds).

## F8. Risks & gaps (most severe first)
1. **Unsigned auto-login + master password** — `login.php:12-80` accepts base64 JSON `{autologin, client_contact_id, client_id}` and signs in with a shared master password (`:26`, `:101`; `dblogin.php` `checkLogInUser`). Knowing two numeric IDs is enough to become that contact on live.
2. **Static secrets in source on both sides** — tokens in B `ApiController.php` (`:2490`, `:2546`, `:2635`, `:1990`, `:4025`, `:4067`, `:4238`, `:4344`, `:5212`…), B `config/services.php:193` + payment key defaults, A (`login.php:36`, `dashboard.php:1308`, `interviews.php:1933`, `OpenstaffingMarketplace.php:666, 893, 936, 1100`, `dbinvoice.php:15`, `rest/api.php:72`), shared AES key / IV (A `appcontroller.php:548-561`, B `MyCPEOneLoginController.php:1153-1172`, `Api/AssureOneTestController.php:25`). One token reused across endpoints, loose `==` checks, can't rotate without a coordinated deploy; token visible in browser URL (#6).
3. **Unauthenticated sign-out writes data** — `MyCPEOneLoginController.php:681-685` updates `mycpe_users` by any column from the URL; `:672` builds SQL with the client IP by string concat. A also calls it with wrong params (no-op bug).
4. **Passwords handled unsafely** — plaintext password sent A → B on reset / change (`filefunctions.php:510-554`), B accepts plain text fallback (`ApiController.php:4516-4517`), A stores password in cookies (`login.php:123-124`).
5. **Open redirects** — A `login.php:280` (`redirect_url`), `:108` (`eu`, encrypted), B `signin` `url` input (`MyCPEOneLoginController.php:223-224`).
6. **Config not in repo** — ~15 A constants (F2) undefined in code; env picked by hostname → local / demo setups can't reproduce live integration.
7. **ID confusion** — B mixes `users.id` and `mycpe_users.id`, falling back to the wrong one (`CommonProfileController.php:286-288`, `TeamProfileNewController.php:135`).
8. **Dead or orphan code** — A `rest/api.php` `login` / `logout` reference missing models; A update-profile / company-profile tasks have no B caller; B payment `save_mapping_url` / `direct_pay_url` marked TBD.
9. **Demo URL mismatch** — menu access demo `demo.entigrity.com/rest/api.php` vs invoices demo `demo.entigrity.com/erp_entigrity_client_panel/…` → one is probably wrong (UNVERIFIED).
10. **Tight coupling / availability** — on live, A can't be reached when B login is down (`sendToMyCPE`); B billing tab fails when A is down (no cache for invoices).
11. **Debug exposure** — A `display_errors=1` (`config.php:22-23`); B `?session_debug=<Ymd>` prints the whole session (`app/Http/Middleware/FirewallMiddleware.php`).

## F9. Implications for the Client mobile app
- **Login:** B is the source of identity. A real Client app should sign in through B and receive a proper per-user token. Do **not** reuse the master-password / `s` auto-login / static-token patterns. Today the Client tab opens without login (Part E #1) — fine for the prototype.
- **No existing API returns client-panel data to a mobile app.** B's mobile API (`api/mobile/*`) is learner-only; A's `rest/api.php` has one useful function. Production needs a new authenticated API on A (or a B gateway) — keep the prototype's mock data shapes aligned with A field names (F4, F6).
- **Access gate:** only `erp_client_status = 1` users get the client app; others → "Hire offshore staff" onboarding.
- **Permissions:** reuse A's role permission JSON (`is_list`, `is_menu_visible`, add / edit / delete / download) for menus and "No access" states; B already depends on the same source for 3 flags.
- **Invoices tab:** mirror B's billing tab contract — filters (invoice no., date range, project, staff, Paid / Unpaid), employees per invoice, CSV, timesheet ZIP per invoice, bulk ZIP with progress (async polling).
- **Billing details / payments** live in system C via B — out of A's scope; show only if `billing_details` is allowed.
- **Profile edits** (my / company) must still sync to MyCPE (contact / firm sync, F4 #14-#15).
- **Other Modules & Services, News & Insights, Resources** come from B (`mm` / `es` login payload, `mycpe-service-sso`, `news-and-insights`, `cms-api/listing`).
- **SOP / goals** open the staff user panel (D) — on mobile open in the in-app browser.
- **Security:** no secrets in the app bundle, no tokens in URLs, no stored passwords, HTTPS only, short-lived tokens.
